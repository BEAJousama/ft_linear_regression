# ft_linear_regression

This project predicts a car's price from its mileage using **one-feature linear regression**. `train.py` learns the line with batch gradient descent; `predict.py` uses the saved line. The implementation uses only the Python standard library. It does not call a regression or optimization library.

## Run it

From this directory, with Python 3:

```sh
python3 train.py
python3 predict.py
```

The predictor asks for mileage in kilometers. For example, entering `100000` after training prints approximately `Estimated price: 6354.70`.

Run `train.py` again whenever `data.csv` changes. It overwrites `model.json`. If `model.json` is absent, `predict.py` uses `theta0 = 0` and `theta1 = 0`, as required by the subject, so every estimate is `0.00` until training.

## Files and code flow

| File | Purpose |
| --- | --- |
| `data.csv` | Training examples with `km` and `price` columns; 24 cars in the supplied dataset. |
| `train.py` | Reads the data, learns two parameters, and saves `model.json`. |
| `predict.py` | Prompts for mileage, loads the parameters, and prints a price estimate. |
| `model.json` | Generated by training. It contains `theta0` and `theta1` in original units. |

### `train.py`, step by step

1. `load_data()` reads each CSV row as a pair `(km, price)`. It checks the header, numbers, finite values, nonnegative mileage, and whether there is at least one example. Its line numbers make malformed rows easier to find.
2. `train(rows)` chooses `scale = max(1, largest mileage)` and replaces each mileage with `x = km / scale`. This puts the supplied mileage values between 0 and 1. Prices remain in their original units.
3. The two training parameters start at zero. Each of the 10,000 iterations computes the prediction error for **every** car and accumulates both gradients. It calculates `next_theta0` and `next_theta1` from the current parameters, then assigns both new values together. The learning rate is `0.1`.
4. The trained slope applies to scaled mileage. Before saving, `train()` divides it by `scale` so `theta1` means price change per **actual kilometer**. The intercept needs no conversion.
5. `main()` writes `model.json` and prints the learned equation.

### `predict.py`, step by step

1. `main()` prompts for one nonnegative, finite mileage value.
2. `load_model()` reads `theta0` and `theta1` from `model.json`. If the file does not exist, it returns `(0, 0)`. A damaged model produces an error that tells you to train again.
3. The final estimate is calculated directly as `theta0 + theta1 * mileage` and displayed with two decimal places.

Both scripts locate their files beside the script itself, so they work even if launched from another directory. Neither script asks for a currency because the dataset does not identify one.

## The theory

### 1. Hypothesis: a straight line

For a mileage `x`, the model predicts:

```text
h(x) = theta0 + theta1 * x
```

`theta0` is the intercept: the model's predicted price at zero mileage. `theta1` is the slope: the predicted change in price for one extra kilometer. A negative slope means the predicted price falls as mileage rises. The intercept is a mathematical part of the line, not a reliable valuation of a new car: zero kilometers lies outside this dataset.

### 2. Error and cost

For training car `i`, define its error as:

```text
error_i = h(x_i) - price_i
```

The training objective is mean squared error with a convenient factor of one half:

```text
J(theta0, theta1) = (1 / (2m)) * sum(error_i^2)
```

Here `m` is the number of cars (`24` in the supplied CSV). Squaring makes positive and negative errors count equally and penalizes large misses more. The factor `1/2` cancels the `2` produced when differentiating a square. It does not change which line minimizes the cost.

### 3. Gradients and updates

The partial derivatives tell us how the cost changes as each parameter changes:

```text
dJ/dtheta0 = (1/m) * sum(error_i)
dJ/dtheta1 = (1/m) * sum(error_i * x_i)
```

Why is the second derivative multiplied by `x_i`? Because the derivative of `theta0 + theta1*x_i` with respect to `theta1` is `x_i`. For `theta0`, that derivative is `1`.

Gradient descent moves **against** each derivative, with step size `learning_rate`:

```text
new_theta0 = old_theta0 - learning_rate * dJ/dtheta0
new_theta1 = old_theta1 - learning_rate * dJ/dtheta1
```

Both gradients are calculated before either parameter changes. This is the simultaneous update required by the subject. Because every iteration uses all `m` cars, this is **batch gradient descent**.

### 4. Why mileage is scaled

The raw mileages reach `240000`. Multiplying the slope gradient by those values would make a useful learning rate for the intercept far too large for the slope. Training instead uses `z = km / scale`, where `scale` is the largest mileage. The same gradient formulas then use `z` in place of `x`:

```text
training_prediction = a + b * z
                  = a + (b / scale) * km
```

Therefore the saved parameters are `theta0 = a` and `theta1 = b / scale`. The saved model still follows the assignment's exact prediction form in actual kilometers. For this dataset, `scale = 240000`.

The constants `learning_rate = 0.1` and `iterations = 10000` give a stable, converged result for the supplied data after that scaling. A different dataset could need different values or a different scaling rule.

## What the result means

On the supplied dataset, training produces approximately:

```text
price = 8499.60 - 0.02144896 * km
```

So an extra 1,000 km lowers the model's estimate by about `21.45` price units. At 100,000 km, it predicts `8499.60 - 0.02144896 * 100000 ≈ 6354.70`.

The model uses mileage only; age, make, condition, and other factors are absent. Its predictions are most defensible near the observed range of `22,899` to `240,000` km. Far outside that range, the straight line may give unrealistic results, including negative prices. The predictor leaves the equation unchanged rather than hiding that limitation.

## Defense checklist

- **Why two programs?** Training finds and saves the parameters. Prediction reads them and can run independently afterward.
- **What is learned?** Only `theta0` and `theta1`; the CSV supplies the examples.
- **What is `m`?** The number of training examples, not the mileage.
- **Why subtract the gradients?** The gradient points toward increasing cost; subtraction moves toward decreasing cost.
- **Why update simultaneously?** Both gradients must describe the same line from the current iteration. Changing one parameter mid-calculation would use mixed old and new values.
- **Why scale mileage?** It controls the size of the slope gradient and lets one learning rate work for both parameters. The slope is converted back before prediction.
- **How do you judge the fit for the required evaluation?** Compare a prediction with a known CSV price and explain why a gap is normal. This does not establish performance on new cars.
- **What happens before training?** Missing `model.json` means both parameters are zero, so the estimate is zero.
- **What do libraries do here?** `csv` parses the file, `json` saves parameters, `math` checks finite numbers, and `pathlib` finds files. The regression and gradient descent are written in `train.py`.

For a live demonstration, run `python3 train.py`, inspect `model.json`, then run `python3 predict.py` and enter `100000`. You can point from each printed value to the equation above.
